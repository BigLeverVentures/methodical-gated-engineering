# Platform support and release qualification

Release disposition: **GO-WITH-LIMITS** for the independently checked capabilities below. The supported scope is local macOS Claude Code and managed Codex CLI at the named versions below, with the observed routing and selected-record continuity described here. This is not a blanket certification of every adapter or client configuration. The two native artifacts are published in [release 0.11.0](https://github.com/BigLeverVentures/methodical-gated-engineering/releases/tag/v0.11.0); portable hosting remains separate. The [testing appendix](testing-0.11.0.md) records the qualification baseline and the limits of its evidence.

| Artifact | Installation surface | Capability | Qualification |
|---|---|---|---|
| Claude Code adapter | Local interactive Claude Code; normal plugin marketplace and trust | Shared method, native Agent routing, project checkpoints | Historical baseline, feedback and stale-denial passes; native source finalization and independently checked process-controlled automatic-boundary continuation passed |
| Codex managed CLI workers | Local macOS native CLI; packaged `dispatch-cli` after approved intent preparation | Shared allocation policy, exact sealed stdin, owned process and project evidence | Baseline and fresh feedback delivery, native source finalization and process-controlled automatic-boundary continuation observed on CLI 0.163.0-alpha.10.2 under tested controller configurations; denial controls have deterministic coverage |
| Codex native child-hook routing | Local desktop/native child tool with normal trust | Candidate integration | Suspended after failed native dispatch; not a supported routing path |
| Portable Agent Skill | An Agent Skills-compatible reader | Common workflow instructions and resources | Instructional package only; native controls require an adapter |

The completed fixture proof supplies historical evidence for the method, selected model availability, review/fix cycles and record recovery. It used synthetic projects and external evaluation orchestration. It does not establish general automatic allocation, production installation, causal savings or universal host compatibility.

## Live worker guard

The CLI coordinator can receive a worker guard check through the synchronous Stop hook on both hosts. A local two-worker fixture used native background Agents in Claude Code and managed CLI workers in Codex. In both, the Stop hook delivered a second check after a coordinator status reply left the stall unresolved. Independent work staged its result during the stall. The coordinator then resumed the original attempt and verified changed, correlated patch output.

Both coordinators accepted both patches. Codex used clean managed-process receipts. The Claude Code 2.1.312 rerun used an explicit completion notification for each correlated background Agent, alongside its native stop. The Claude adapter recognizes the tested parent-transcript notification format and checks the live task registry before settling an unknown stop. Missing, mismatched or unsupported evidence leaves the patch pending. These runs qualify continuation of an active local CLI turn. An ended turn requires resuming the owning session. The fixture used cooperative write scopes.

## Coordinated delegation

A matched local CLI fixture used the same four named tasks, approved scopes, two worker
slots and frozen checks on both hosts. The initial pair overlapped, both leads refilled a
slot for the third independent task, and the final worker received all three accepted
prerequisite patches. Each lead integrated four verified patches and passed the shared checks.

Claude used native background Agents. The broker-free Codex rerun used the installed
plugin with normal hook trust. The coordinator issued the exact ready claims from its
session, and the plugin's Stop hook started the managed workers in the workspace-write
sandbox. Each worker's manifest records its configured model and effort. Backend
worker settings remain unobserved. See [coordinated setup](setup.md#coordinated-builds)
for the installed hook route.

## Native evidence and scope

A production package must activate without a proof marker, deliver the intended common instructions, and uninstall without deleting project records or unrelated settings. One baseline and one freshly reproduced failure case per host must show the shared policy reaching the actual native child invocation. Runtime rewrite logs alone do not prove that consumption.

Four separate fresh native destination contexts passed records-only recovery: Claude→Claude, Claude→Codex, Codex→Claude and Codex→Codex. Each restored captured records and passed pre/post verification; Codex destinations used the managed CLI. These destination passes establish only their captured-record recovery scope.

Separate native source sessions ran the production `checkpoint-finalize` lifecycle and observed automatic context boundaries under these process-local controls:

| Native source | Configured model / effort | Process-local controls | Observed boundary |
|---|---|---|---|
| Codex CLI | `gpt-6-luna` / high | `model_auto_compact_token_limit=110000`; context-window override unset | Automatic boundary after nine admitted pressure reads; records-only continuation passed |
| Claude Code | Sonnet 5.5 / medium | `CLAUDE_CODE_AUTO_COMPACT_WINDOW=150000`; `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=60` | Automatic boundary after seven admitted pressure reads; independently checked records-only continuation passed |

The checks preserve checkpoint and routing bytes, newer rulings and dirty records, pending intents, findings and outstanding review debt. Claude additionally verified selected captures, ordinary tree bytes/index/modes and six captured dispatch-dependency modes; preservation of its entire ignored directory and fixture journal was not independently established and is excluded. Codex separately verified its full fixture snapshot and prior journal prefix. An older checkpoint is not made current by compaction or by a successful finalizer at an earlier read. These process-controlled checks do not establish default-window thresholds, complete conversation preservation or desktop child-hook dispatch. Changed executable finalization or recovery paths require affected qualification again. An interrupted checkpoint, missing evidence or unknown dispatch remains unresolved.

Some native tools can bypass general tool hooks; these hooks are cooperative workflow controls, not a security boundary. Record the installed commit and package inventory alongside client versions. Do not assume browser/cloud surfaces, a different client release, public directory admission, or Hugging Face hosting supplies the same execution controls.

## Runtime and installation limits

Native packages include compiled JavaScript and require Node.js >=22.13, as stated in the core package manifest. Installation never downloads a compiler or model SDK. Development builds use pinned dependencies. Ordinary project trust, sandbox controls and child execution approval remain active.

Claude routing rewrites tool arguments without granting a permission decision. The suspended Codex native-child integration requires a narrowly scoped PreToolUse allow result to accept replacement Agent arguments; the adapter never grants PermissionRequest, shell, sandbox or child permissions. Managed CLI workers inherit native authentication, trust, sandbox and approval configuration.

A fresh session is the activation check after installation or update. Hot reload and application restart behavior are client-dependent; no installer restarts the app or closes other work.


The managed Codex CLI transport is implemented for macOS/Linux with an atomic core launch claim, fixed native model/effort/feature arguments and inherited sandbox configuration, strict bounded JSONL, owned process-group cleanup and private project evidence. Hermetic Node-process fixtures exercise this boundary. Managed delivery has been observed on macOS with the exact CLI version listed above, in a project configuration that disabled the installed legacy and proof plugins locally. A later feedback attempt failed at startup on inherited legacy hook parsing; that consumed operation remains unknown. The candidate is not qualified under arbitrary installed-plugin configurations.

Model and effort were configured through native CLI arguments; backend model and effort telemetry was unavailable. Both multi-agent feature overrides are set false, and no worker tool use was observed in the baseline delivery. Tool unavailability has not been independently established. Native authentication, trust, sandbox and approval configuration are inherited. These are cooperative workflow controls. Linux remains covered by implementation and offline fixtures only. A fresh feedback case subsequently passed on a trusted controller using the same CLI version, with configured `gpt-6.1-sol`/high, exact bound delivery and review debt preserved. Automatic-boundary evidence and the four destination recovery passes have only the process-controlled and records-only scopes stated above.

Owned process-group cleanup does not contain descendants that escape into another group. After the deadline and bounded TERM/KILL grace, held output pipes are forcibly closed and recorded incomplete; unconfirmed leader reaping remains explicit unknown debt. Clean completion requires genuine output EOF and confirmed zero leader exit. Escaped descendants and backend termination remain unobserved.

## Artifact identity and release limits

The final documentation build regenerates package inventories and the shared method hash for the host-route reference clarification. Executable runtime, checkpoint/dispatch paths, hooks, profiles and allocation policy remain byte-for-byte unchanged from the tested runtime. Live evidence is reused through that dependency comparison; the newly generated whole packages were not themselves live-tested byte-for-byte. Frozen qualification packages and earlier failed or stopped results remain preserved. The Claude actor-local copy preserved all canonical payload files; additional client-generated type files do not imply a changed canonical package.

Other client versions, Linux native execution, default-window compaction thresholds and arbitrary installed-plugin configurations remain unqualified. Configured settings do not prove backend reasoning effort, descendant-tool unavailability, escaped-process containment or backend termination. The controls provide neither a protected billing boundary nor a currency cap, and no savings or review-quality improvement is established. Portable distribution, including Hugging Face hosting, supplies instructional content and no native execution capability.
