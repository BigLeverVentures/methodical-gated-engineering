# Portable skill checkpoint

Status: offline distribution prototype. No new native activation, model evaluation, installation or
publication is established by this checkpoint. The production plugin is unchanged.

## Findings and changes

| Dependency found in the shared instructions | Change |
|---|---|
| Required native child/question APIs and platform profile | Shared method uses declared adapter capabilities and dated platform guidance; unavailable controls stay explicit |
| Hook observations asserted as universal freshness | Native observation rule moved to synthetic proof protocol; shared records state capture gaps |
| Required Node helper and marked Python fixture | Kept in native proof protocol/runtime; portable skill contains instructions and references only |
| Python correctness seat treated as universal | Shared method selects the actual stack; Python remains the synthetic proof's explicit floor |
| Native compaction and binary snapshots implicit in handoff | Manual records, complete adapter checkpoints and actual native lifecycle observations are distinguished |
| Hardened run-live admission treated as the only live route | Original guarded runner stays closed under its existing checks; explicitly authorized monitored diagnostics name their actual limits |

Generate all three distribution artifacts with the existing `scripts/package.sh OUTPUT` command.
The additional `OUTPUT/portable/methodical/` folder contains SKILL.md, two shared references,
license/notices and proof-package.json integrity/provenance. Its canonical method and reference bytes
are identical to the native skills. No second maintained method, host runtime, model profile,
private data, scorer, synthetic fixture or hook installation is included in that folder.

Native SessionStart injects the canonical method, shared references, synthetic protocol and overlay.
Both native skills link that protocol. Existing compiled checkpoint/policy contracts remain unchanged:
two named hosts, synthetic Git fixtures, schema-v1 helper records and the Python fixture review floor.
Those bounded proof helpers are not a portable runtime or dependencies of instructional skill use.
Adding a third executable adapter requires its own profile, codec/receipt integration and qualification;
manual notes do not impersonate full helper checkpoints or prove third-host interoperability.

## Format and capability limits

The [Agent Skills specification](https://agentskills.io/specification) defines SKILL.md metadata and
optional resources. [Hugging Face's skill documentation](https://huggingface.co/docs/hub/agents-skills)
describes skill distribution for supported agents. Consulted 2026-10-16. Format compatibility is a
packaging property; this artifact has not been admitted to or published through Hugging Face.
The minimal frontmatter uses only name, description and license: the local Codex skill validator
rejects the specification's optional compatibility field, so capability requirements stay in the
shared body/references instead of depending on that optional field.
Native model/effort controls, independent subagents, hooks, telemetry and automatic compaction come
from the executing host and its adapter, with explicit unavailable/unverified dispositions.

Offline checks verify relocation/reference closure, complete hashed inventory, canonical edit
propagation, populated-output refusal and preserved native startup instructions. Mutated/missing
files and lost native protocol fail those checks. They do not establish behavioral conformance.

## Evidence capture and recovery verification

Schema-v2 checkpoints add explicit bounded support capture; `work.evidence` remains opaque.
See [record semantics](core/records.md) and each native overlay for descriptors and standalone commands.

The synthetic identity encoding is SHA-256 of raw UTF-8 `methodical-proof-fixture.json` bytes
concatenated with `git rev-list --max-parents=0 HEAD` text after trimming only its complete leading
and trailing whitespace. Multiple root commits retain their internal newline bytes. Saved tree hashes
use decimal `(mode & 0777)`, a colon, then raw file bytes; saved index hashes use raw
`git ls-files --stage -z` bytes. The same helper computes these identities for publication and recovery.
The pre-restore verifier checks bundle integrity and clean destination identity/HEAD/branch/index/tree
without requiring yet-to-be-restored plan bytes. Post-restore separately checks saved dirty state,
plan/ruling/lesson references and required archived support. Neither verification mode writes any file
or metadata, including on failure; it cannot certify unseen chat facts or prevent later concurrent edits.

New package qualification must name its exact source and artifact hashes. Historical native results
remain bound to their original package; this source change does not upgrade those results.
