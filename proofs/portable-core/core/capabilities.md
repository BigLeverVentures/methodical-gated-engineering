# Capability contract

This portable skill supplies instructions. Distribution does not supply host execution controls.
For facilities needed by the requested action or assurance claim, record
available/manual/unavailable/unverified, the evidence reference and any limit. Leave unassessed
facilities unverified by default. Assess the relevant subset of: activation/removal; scoped human decisions; independent reviewer dispatch;
model selection; effort selection; per-role usage; active-window telemetry; durable project writes;
complete checkpoint publication/freshness; native manual compaction; native automatic compaction;
and fresh-session/cross-host recovery. Packaging success does not mark any native capability available.

Manual questions and documented user decisions can support cooperative gates. Manual reviewer
handoffs can satisfy a lens only when the actual independent review and candidate binding are
observed. Without that facility, preserve review debt and stop before claiming review clearance.
Manual model changes require an actual supported control and evidence; otherwise record unavailable.
Do not require a native tool name, environment variable, hook or slash command on an unknown host.

File access supports instructional work records. It does not alone prove atomic publication,
complete dirty-byte preservation, automatic capture of chat decisions or cross-host restoration.
When required guarantees are unavailable, retain records and describe the partial result. Automatic
compaction/recovery stays unqualified until exercised on the actual adapter and surface/version.

The existing compiled proof helpers are deliberately restricted to marked synthetic Git fixtures
and two named host tags. They are not dependencies of this instruction-only package and are not a
third-host runtime. Host profiles, native hooks and their trust/loading controls belong to adapters.
The current policy's Python correctness seat is a fixture choice; portable work selects correctness
lenses from the actual stack. Preserve the project's required assurance floor.

Schema-v2 proof helpers expose separate read-only pre-restore and post-restore checks and explicit
captured-evidence mappings. Offline codec/package checks establish those tested code paths only.
Native pre-write ordering, hook exemption and records-only recovery remain version/surface-bound
observations. External or unavailable support remains a limitation; legacy v1 evidence coverage is
unknown. Exact restoration does not establish unrecorded conversational freshness.
