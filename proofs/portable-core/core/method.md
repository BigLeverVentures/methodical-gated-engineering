# Methodical gated engineering

Use one method for scoped engineering work: brainstorm → North Star → plan → deepen when needed →
plan review → work → work review → compound → compact. Name the current step. Read the project's
written goal, current plan, scope and active rulings before acting. Existing explicit authorization
and standing grants remain valid within their scope; a quotation alone creates no new authority.
Bind implementation authority to the current plan revision and scope. A material scope or plan
change needs appropriate authority. Honor an explicitly waived step and drop a declined offer for
that moment. Checkpointing never authorizes a commit, push, merge, installation or expenditure.

## Establish capabilities

Use [capabilities](references/capabilities.md) to assess only facilities needed for the requested
action or assurance claim, including when the execution surface changes. Leave unassessed facilities
unverified; routine work does not require a full host inventory. For relevant facilities, state
available, manual, unavailable or unverified. Instructions express
cooperative workflow behavior; host enforcement, independent child contexts, model/effort controls,
usage telemetry and compaction require separate adapter evidence. An unavailable required facility
leaves a named limitation or outstanding review debt. Never simulate a native subagent by calling
another model CLI/API or label a same-context self-review independent.

## Allocate resources from verified feedback

Use deterministic tools for deterministic questions. Start model and effort selection from dated,
published guidance for the actual platform and available account, recording the Methodical role
mapping separately. Use an adapter's frozen profile when one exists. Model and effort are separate
controls; equal effort labels across providers do not establish equal effort. The person's parent
session settings remain their choice. Without a supported control, retain the setting and record
the limitation rather than claiming a requested selection executed.

Give each worker/reviewer the smallest useful brief: goal, plan revision/hash, scope, candidate,
acceptance criteria and relevant evidence. Preserve required North Star, code-grounded, simplicity,
rigor and stack-matched correctness review coverage and the approved risk floor. A cheaper worker
pass does not remove required reviews or a required final backstop.

Independently reproduce a failed acceptance check or material finding before changing resources.
Distinguish environment/dependency, output-format, diligence, capability and recurring failures.
A tool or environment defect needs correction, not a more expensive reasoning retry. Record
attempts, review cycles, material findings and all-role usage. Escalate model and/or effort only
within the approved policy and batch allowance on verified relevant feedback. Fix material findings,
run independent checks, then re-review affected lenses. Bind final review to the exact candidate;
a new code commit invalidates that candidate's pass. Stop with unresolved debt when the allowance
is exhausted. Do not claim savings or superiority from an unused escalation path.

Correlate requests with actual per-session/child/turn receipts. Requested, configured and observed
settings are distinct; absent telemetry remains unknown. Include setup, orchestration, reviewers,
retries, compounding and recovery in costs. Cached input is part of input and reasoning is part of
output; cumulative usage is not active-window occupancy or an invoice.

## Compound before compacting

Investigate non-obvious problems with real diagnostics. Write each useful discovered lesson with
its evidence and consequence in docs/solutions/ and index it. A generic recap or prewritten answer
is not compounding. Preserve active rulings verbatim, unresolved findings/review debt and the exact
next action in durable project records promptly. Follow [work records](references/records.md) for
portable handoff semantics and the distinction between manual notes and an adapter checkpoint.

Use observed active-window telemetry where available; label estimates and unknown headroom honestly.
At useful work boundaries, save important new decisions and findings instead of waiting for a
compaction hook. Before requested compaction, compound and save the latest complete handoff using
the supported facilities. Honor explicit preservation decline without a replacement gate or repeat
offer, record the decline internally and never present an older checkpoint as current.

Only an observed host action establishes native manual or automatic compaction. A skill cannot
promise to intercept an unexpected boundary. Resume from the latest complete records, read indexed
lessons, verify repository/candidate and dirty-state freshness, reconcile newer decisions, and take
the recorded next action. Never apply a saved patch over newer work automatically. Cross-host resume
uses project records rather than the original chat or another host's transcript.

## Evidence boundary

Preserve failed, stopped, pending and successful attempts with source/package/profile versions,
missing telemetry and current review SHA. Offline checks establish their tested properties; native
activation, automatic compaction and behavioral recovery require separate observations. Run live
work only within existing explicit authority and a declared batch allowance/stop rule. State whether
limits are monitored or enforced and what in-flight exposure remains. A token target is not a hard
currency cap; missing hard-cap evidence cannot be relabeled as enforcement. Installation, account,
credential and funding changes require their own applicable authority.
