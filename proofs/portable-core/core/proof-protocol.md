# Synthetic native proof protocol

This protocol narrows the shared method for the existing Python proof; it is not a production
replacement. Activate only in a marked synthetic fixture. Read its goal, plan and scope ruling;
ask the operator for the scoped implementation decision, bound to actual plan hash and scope.
Both existing native adapters must supply real native worker/reviewer contexts and question controls.
Use the packaged platform profile after the operator freezes available identities/efforts. Request
settings via the helper policy output; receipts must identify actual native sessions/children/turns.

Preserve North Star, code-grounded, simplicity, rigor and Python correctness seats. Lean/full also
require the final backstop; full maps demanding review seats to the backstop setting. The proof
policy allows one escalation and two resource attempts, never lowering the risk floor. Bind the
backstop to the exact candidate commit; material repair requires affected-lens re-review.

Investigate the local dependency with a real diagnostic and compound a NEW useful indexed lesson.
No secret lesson ID or prose template is required. The independent evaluator checks the held-out
probe; a trusted operator binds a semantic lesson judgment to lesson, index and diagnostic hashes.
Keep held-out checks outside the actor repository; public checks are only smoke checks.

Record every new user decision, finding, acceptance outcome or next action using the packaged
helper `record ROOT KIND REF` before relying on a checkpoint. Native PostToolUse observations
invalidate semantic freshness except the exact standalone helper invocations documented in the
overlay. Unknown prompt coverage never guarantees capture of all chat facts.

Publish only through the synthetic helper, which captures tracked/untracked work and common records.
Use checkpoint status immediately before compaction; reconcile stale state. Native compaction is a
separate host action. An explicit preservation decline must not call an older checkpoint current.

All run records remain private, including failures and missing telemetry. Native install/trust,
child loading, manual/automatic compaction and recovery remain separately observed acceptance.
The legacy run-live.sh route still requires its tested guard/admission/cancellation/isolation
coverage; this skill does not open that route. A separately authorized monitored native diagnostic
must name its manifest, exposure and stop behavior honestly; it cannot claim a hard billing cap.
Do not alter accounts, credentials, funding or protected configuration by inference.

For fresh-session recovery, use the overlay's standalone `verify ROOT BUNDLE pre-restore` command
before the first restoration write. Inspect every check and stop on failure. This read-only guard
compares against the saved clean base, not the saved dirty tree. Restore saved bytes/index/modes,
resolve required evidence through the archive manifest, then run `verify ROOT BUNDLE post-restore`.
Keep bundle integrity, destination compatibility, restored state, evidence completeness and semantic
freshness separate. A successful post-restore match cannot retroactively establish the pre-write guard.
The verifier reports unrecorded-chat freshness as unknown; a timestamp or opaque evidence label is
insufficient. Native command ordering and hook read-only behavior require actual native observation.
